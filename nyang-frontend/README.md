# 냥대리 · 나의 업무 메이트

데스크톱 웹 앱. `/cat/`에서 문서 기반 FAQ, 일정·할 일, 고양이와의 상호작용, 질문 활동과 로그인 없는 공개 체험 게시판을 제공합니다.

## 채팅 화면

첫 화면은 큰 냥대리와 배경을 유지하면서 메시지 입력창을 바로 표시합니다. 첫 메시지를 보내면 같은 캐릭터 요소가 작아져 첫 답변의 프로필 위치로 이동합니다. 대화에서는 사용자 메시지를 오른쪽, 냥대리 답변을 왼쪽에 표시하고 입력창은 하단에 고정합니다. 눈 깜빡임·작은 몸 움직임·움직임 끄기·다크 모드를 지원합니다. 직접 입력을 이유로 화내는 반응은 제거했습니다.

질문 예시는 입력창에서 열 수 있습니다. 출처·일정 제안·익명 게시판 제안은 답변에 포함됩니다. 대기 중 입력한 초안은 답변이 표시될 때 유지하며, 새 대화를 시작하면 이전 대기 응답은 취소합니다. 대화 기록은 현재 탭에서만 유지합니다. 답변은 기존 샘플 FAQ·키워드 탐색이며 AI 모델을 새로 연결한 변경은 아닙니다.

## 로그인 없는 방문자 모드

현재 화면은 `/api/visitor`를 사용합니다. 로그인이나 직원 등록 없이 게시판, 출석, 질문 레벨, 포인트, 츄르, 하트, 꾸미기에 접근할 수 있습니다. 게시판은 방문자 간에 공유됩니다.

서버가 256비트 무작위 방문자 쿠키를 발급하고 해시한 ID로 활동을 구분합니다. 쿠키는 HttpOnly / SameSite=Lax이며 HTTPS에서 Secure를 적용합니다. 같은 브라우저에서 기록이 이어지며 쿠키 삭제·다른 브라우저에서는 별도의 방문자로 시작합니다. 개인정보나 계정 이메일은 받지 않습니다.

모든 방문자가 근거를 포함해 답변할 수 있습니다. 화면에는 ‘체험 답변 · 공식 확인 전’으로 표시합니다. 실제 담당자 인증 기능은 현재 화면에서 제공하지 않습니다. 직원 관리 UI와 로그인·로그아웃 링크를 제거했습니다.

방문자 데이터는 새 `visitor_*` 테이블에만 저장됩니다. 기존 직원용 `/api/community`의 인증과 권한 검사는 유지하며, 기존 회사 게시글·보상을 공개 체험 공간으로 복사하거나 노출하지 않습니다.

## 보상과 게시판

- 서로 다른 질문 한 개에 10 P, 질문 경험치 1. 같은 정규화된 질문은 방문자당 한 번, 하루 최대 20개입니다. 레벨 기준은 0/5/15/30/50개이며 업무 능력 평가가 아닙니다.
- 출석 뽑기는 한국 시간 기준 하루 한 번, 무료입니다. 5 P 50%, 10 P 30%, 츄르 1개 15%, 츄르 3개 5%. 서버 난수·서버 날짜를 사용하며 다시 요청해도 같은 결과입니다.
- 냥대리가 모르는 질문에만 익명 게시 제안을 표시합니다. 작성 내용을 검토하고 공유 동의를 체크한 뒤 게시합니다. 개인별 정보 질문은 입력란을 비워 일반적인 절차 질문으로 바꾸도록 안내합니다.
- 방문자가 다른 사람의 질문에 좋아요를 누르면 작성자에게 5 P를 지급합니다. 본인 좋아요·중복 좋아요는 차단합니다. 좋아요 취소 기능은 없습니다.
- 게시판에는 작성자 이름·이메일·사용자 ID를 반환하지 않습니다. 보상 지급을 위해 방문자 연결은 서버에 남으므로 운영 데이터에 대한 완전한 익명성을 보장하는 기능은 아닙니다.
- 누구나 답변할 수 있습니다. 답변에는 공개 체험 표시·작성일·근거가 표시되며, 공식 담당자 답변으로 검증된 내용이 아닙니다. 방문자당 답변은 하루 최대 30개입니다.
- 최근 200개 질문, 전체/답변 대기/답변 완료/내 질문 필터와 질문 검색을 제공합니다. 게시 한도는 하루 10개입니다.
- 출석 츄르를 먼저 사용하고, 없으면 10 P를 사용합니다. 츄르를 주면 하트 3개를 모을 수 있고 리본 3♥, 왕관 5♥, 별빛 8♥로 꾸밀 수 있습니다.
- 쓰다듬기는 좋아함 60% / 싫어함 40%. 좋아하는 경우 중 3%에 꼬리 흔들기와 5 P 보상이 발생합니다. 서버에서 판정하며 4.2초 쿨다운이 있습니다.

새 보상은 방문자별로 서버 데이터베이스에 저장합니다. 조작 가능한 기존 브라우저 체험 포인트는 서버 보상으로 가져오지 않습니다. 기존 로컬 저장 키는 삭제하지 않습니다.

## 현재 범위

실제 서버 기능: 자동 방문자 연결, 공개 익명 게시판·체험 답변, 좋아요·포인트, 출석, 질문 레벨, 츄르·하트·꾸미기.

기존 체험 기능: 챗봇의 답변은 샘플 FAQ와 키워드 검색입니다. 회사 실제 문서 AI 검색이 아닙니다. 일정·할 일·추가 샘플 자료는 브라우저에 저장합니다. Google Workspace·Slack 연동, 실제 상품 지급·사원 순위, 회사 SSO, 자동 이메일 알림은 이번 구현에 포함되지 않습니다. 실제 회사 규정과 운영 방침은 담당자가 관리해야 합니다.

## 개발

Sites Vinext + Cloudflare Workers + D1. `public/`에 기존 화면과 자산, `app/api/visitor/route.ts`에 방문자 HTTP 경계, `lib/visitor.mjs`에 방문자 ID·데이터 격리, `lib/community.mjs`에 공통 보상 로직, `db/schema.ts`와 `drizzle/`에 데이터 구조와 규칙이 있습니다.

```text
npm ci
npm run prepare:site
npm run check
npm run build
```

배포에는 Sites skill의 install/build/source workflow를 사용합니다. `.openai/hosting.json`의 기존 Site ID와 D1 `DB`를 유지합니다. 이미 적용한 migration은 수정하지 않습니다.

로컬 개발:

- 방문자 기능에는 관리자 환경 변수나 로그인 설정이 필요하지 않습니다.
- 최초 빌드 후 각 SQL 파일을 순서대로 로컬 D1에 적용합니다:
  `node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/<파일명>.sql`
- `npm run dev -- --port 4173 --hostname 127.0.0.1` 후 `/cat/`에 접속합니다. 방문자 기능은 로컬 테스트 로그인과 무관하게 동작합니다.
- 개발 데이터베이스와 `.dev.vars`, `.wrangler`, `.sites-runtime`은 배포 소스·아카이브에 포함하지 않습니다.

검증: 기존 FAQ/일정/고양이 보상 테스트, SQL migration을 적용한 SQLite 서비스 테스트(로그인·회원 경계, 직원/담당자 권한, 익명 응답, 좋아요, 출석, 질문 중복·한도, 동시 요청·재시도), 방문자 쿠키 유지·공유 게시·좋아요·출석·꾸미기, 직원 데이터와의 격리 테스트 및 로컬 D1 브라우저 흐름.

## 사내 문서 검색 연결 (main 백엔드)

직원 계정으로 질문하면 서버의 `/api/knowly`가 main 브랜치의 Supabase `chat` 함수(등록 FAQ → 문서 키워드·의미 검색 → AI 요약 → 출처 검증)에 질문을 전달하고, 근거가 있는 답을 기존 답변 카드 모양으로 보여 줍니다. 근거가 없거나 연결 설정이 없으면 기존 샘플 FAQ·키워드 답변을 그대로 씁니다. 질문 예시 버튼, 다른 분야 질문, 개인 정보 질문은 기존 방식으로 처리합니다.

서버 환경 변수(`.env.example` 참고, 값은 Sites secrets로만 설정): `KNOWLY_SUPABASE_URL`, `KNOWLY_SUPABASE_KEY`(publishable key), `KNOWLY_LOGIN_EMAIL`, `KNOWLY_LOGIN_PASSWORD`(Knowly 관리자 화면에서 발급한 직원 계정). 비밀번호와 토큰은 브라우저로 보내지 않습니다. 담당자(admin01) 화면의 FAQ 관리·문서 관리·사용자 관리·검색 모델 설정과 이용통계 하단의 ‘사내 문서 검색 이용 현황·답하지 못한 질문’은 `/api/knowly-admin`을 거쳐 main의 Knowly 관리자 기능(Supabase 테이블, `ingest`·`admin-users`·`admin-settings` 함수, `admin_usage_stats`)을 그대로 사용합니다. 이 기능에는 `KNOWLY_ADMIN_EMAIL`, `KNOWLY_ADMIN_PASSWORD`(Knowly 관리자 역할 계정)가 필요하며, 비어 있으면 기존 샘플 관리자 화면을 보여 줍니다. 서버는 정해 둔 작업만 허용하고 입력을 검사합니다. 냥대리에서는 텍스트 문서(.txt·.md·.csv)와 붙여 넣은 글을 등록할 수 있고, PDF·엑셀 원본 등록은 Knowly 관리자 화면에서 합니다.
